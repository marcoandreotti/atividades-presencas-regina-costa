# Contribuição e versionamento

Este projeto acadêmico será desenvolvido em etapas pequenas para manter um histórico claro e revisável.

## Branches

Crie cada mudança a partir de `main` usando um prefixo e uma descrição curta em kebab-case:

- `feat/cadastro-atividades`
- `fix/presenca-duplicada`
- `docs/instrucoes-execucao`

## Commits

Use mensagens no formato `tipo: descrição`, com verbo no presente e escopo objetivo. Prefira um commit por unidade lógica de trabalho. Tipos comuns: `feat`, `fix`, `docs`, `refactor`, `test` e `chore`.

## Pull Requests e auto-revisão

Abra um Pull Request de cada branch para `main`. Antes de integrar, revise o diff, confirme que os dados de demonstração são fictícios, verifique se a documentação acompanha a mudança e registre no PR o requisito atendido e as verificações realizadas. A integração só deve ocorrer após a revisão.
